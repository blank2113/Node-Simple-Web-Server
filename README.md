# 🚀 Simple HTTP Web Server (Node.js + TypeScript)

Минималистичный, быстрый и отказоустойчивый веб-сервер, написанный на **TypeScript** с использованием встроенного модуля `node:http` без сторонних веб-фреймворков. 

Проект разработан с учетом лучших практик: логика декомпозирована на чистые изолированные функции, внедрена защита от инфраструктурных сбоев, конфигурация управляется через переменные окружения, а раздача статики оптимизирована с помощью потоков (Streams). Сервер полностью готов к масштабированию в режиме кластера через PM2.

---

## 🏗️ Архитектура и жизненный цикл запроса

Архитектура построена на плоском конвейере обработки (Flat Pipeline). Каждая стадия запроса изолирована, что предотвращает падение сервера при некорректных действиях пользователя.

```text
[Клиент] 
   │
   ▼
[Порт :PORT] ──► (Инициализация: проверка EADDRINUSE)
   │
   ▼
[http.createServer] 
   │
   ├──► [parseSafePath] ──────► (Декодирование URL, защита от дефектов)
   │
   ├──► [startsWith] ─────────► (Валидация безопасности Directory Traversal)
   │
   ├──► [resolveStaticFile] ──► (Умный поиск файлов: прямой -> .html -> index.html)
   │
   ▼
[fs.createReadStream] ──► [stream.pipe(res)] ──► [Ответ клиенту]
```

# 🛠️ Спецификация скриптов управления (`package.json`)

В данном модуле описана система автоматизации жизненного цикла приложения. В проекте настроены специализированные npm-скрипты, которые инкапсулируют длинные низкоуровневые CLI-команды компилятора TypeScript и менеджера процессов PM2 в удобные и короткие алиасы.

Все команды запускаются из корневой директории проекта через терминал с помощью префикса `npm run <название_скрипта>`.

---

## 💻 1. Окружение разработки (Локальная сборка)

Эти скрипты предназначены для использования на локальной машине разработчика в процессе написания, отладки и тестирования кода.

### 📦 `npm run build`
* **Команда:** `tsc`
* **Назначение:** Однократная компиляция исходного кода.
* **Описание:** Запускает компилятор TypeScript (`tsc`). Он сканирует все файлы с расширением `.ts` в директории `src/`, выполняет строгую проверку типов на основе правил из `tsconfig.json` и транспилирует код в чистый JavaScript (ES-стандарт), сохраняя результат в production-папку `dist/`.

### 🔄 `npm run watch`
* **Команда:** `tsc -w`
* **Назначение:** Инкрементальная сборка в реальном времени.
* **Описание:** Запускает компилятор в режиме «наблюдателя» (фонового слежения за файловой системой). Процесс остается активным в терминале. Как только разработчик сохраняет изменения (`Ctrl + S` / `Cmd + S`) в любом файле внутри `src/`, компилятор мгновенно пересобирает только этот измененный файл и обновляет код в папке `dist/` на лету.

### 🏃‍♂️ `npm start`
* **Команда:** `node dist/index.js`
* **Назначение:** Стандартный однопоточный запуск приложения.
* **Описание:** Напрямую запускает скомпилированную продакшен-сборку из папки `dist/` с помощью среды выполнения Node.js. Запуск происходит в один поток (Single-thread) внутри текущей сессии терминала. Используется для быстрой проверки работоспособности сервера перед деплоем. 
* *Примечание: Для скрипта `start` зарезервировано специальное правило в npm, поэтому ключевое слово `run` при вызове можно опускать.*

## 🚀 2. Продакшен-окружение (Кластеризация через PM2)

Эти скрипты предназначены для развертывания и управления веб-сервером на удаленном сервере (VPS/VDS). Они переводят приложение в многопроцессорный режим кластера для обеспечения максимальной отказоустойчивости и полной утилизации мощности процессора.

### 🟢 `npm run cluster:start`
* **Команда:** `npm run build && pm2 start dist/index.js --name web-server -i 2`
* **Назначение:** Первичный запуск и разворачивание инфраструктуры сервера в режиме кластера.
* **Описание:** Конвейерный скрипт, выполняющий последовательность действий:
  1. Вызывает скрипт сборки (`npm run build`), гарантируя, что запускается актуальная версия кода.
  2. В случае успешной компиляции оператор `&&` передает управление утилите PM2.
  3. `pm2 start` запускает приложение в фоновом режиме в виде демона (процесс не занимает окно терминала).
  4. Флаг `--name web-server` присваивает группе процессов понятное имя для удобного администрирования.
  5. Флаг `-i 2` инициализирует **2 независимых изолированных инстанса (воркера)** твоего сервера. PM2 автоматически берет на себя роль балансировщика нагрузки (Load Balancer), распределяя входящие HTTP-запросы между этими воркерами.

### 🔄 `npm run cluster:reload`
* **Команда:** `npm run build && pm2 reload web-server`
* **Назначение:** Мягкое обновление кода на «живом» сервере без потери входящего трафика (**Zero-Downtime Reload**).
* **Описание:** 1. Выполняет повторную компиляцию обновленного TypeScript-кода в JavaScript.
  2. Отправляет команду перезапуска в PM2. Вместо полной остановки всего сервера, PM2 перезапускает воркеры строго по очереди. Пока первый инстанс отключается и обновляется, второй воркер продолжает обрабатывать 100% сетевых запросов от пользователей. Когда первый воркер успешно перешел в статус `online`, PM2 обновляет второй. Для конечного пользователя сайт или API остаются доступными каждую секунду деплоя.

### 📊 `npm run cluster:status`
* **Команда:** `pm2 status`
* **Назначение:** Мониторинг состояния и метрик запущенного кластера.
* **Описание:** Выводит в терминал интерактивную таблицу со сводной информацией обо всех запущенных процессах. Позволяет мгновенно оценить:
  * Текущий статус каждого воркера (`online`, `stopping`, `errored`).
  * Аптайм (время непрерывной работы процесса).
  * Счетчик непредвиденных падений и автоматических перезапусков (`restart`).
  * Точечную утилизацию оперативной памяти (RAM) и ядер процессора (CPU) каждым инстансом в текущий момент времени.

### 🛑 `npm run cluster:stop`
* **Команда:** `pm2 delete web-server`
* **Назначение:** Полная остановка приложения и очистка памяти.
* **Описание:** Принудительно завершает работу всех фоновых воркеров веб-сервера, выгружает их из оперативной памяти сервера и удаляет имя `web-server` из списков отслеживания PM2. Занимаемый приложением сетевой порт (например, `:3000`) мгновенно освобождается для системы.
